class ResponsivePage extends StatelessWidget { 
  final double mobileBreakpoint = 600; 
  final double tabletBreakpoint = 1024; 
  @override 
  Widget build(BuildContext context) { 
    double screenWidth = MediaQuery.of(context).size.width; 

 
    if (screenWidth < mobileBreakpoint) { 
      return _buildLayout(context, '📱 Mobile Layout', Colors.blue); 
    } else if (screenWidth < tabletBreakpoint) { 
      return _buildLayout(context, '📲 Tablet Layout', Colors.green); 
    } else { 
      return _buildLayout(context, '💻 Desktop Layout', Colors.red); 
    } 
  }

      appBar: AppBar(title: Text('Responsive Layout')), 
      body: Container( 
        color: color, 
        child: Center( 
          child: Text( 
            label, 
            style: TextStyle(fontSize: 30, fontWeight: FontWeight.bold),

5. A) LEARN ABOUT STATEFUL AND STATELESS WIDGETS.  

1. Stateless Widget  
A Stateless Widget is a widget that does not change once it is built. ∙ Its UI stays the same 
throughout the app’s lifetime.  
∙ Useful when the widget’s data is fixed or comes only once.  
Key Points:  
∙ No internal state to update.  
∙ The build() method is called only once unless external data (like from a parent  widget) 
changes.  
∙ Extends StatelessWidget.  
Example:  
import 'package:flutter/material.dart';  
class MyStatelessWidget extends StatelessWidget {  
 @override  
 Widget build(BuildContext context) {  
 return Scaffold(  
 appBar: AppBar(title: Text("Stateless Example")),  
 body: Center(child: Text("I never change!")),  
 );  
 }  
}  

15 
 



Behavior: The text always remains the same.  
2. Stateful Widget  
A Stateful Widget is a widget that can change when something happens (e.g., user  input, 
button press, API call).  
∙ Has an internal State object that can be modified using setState(). ∙ When setState() is called, 
Flutter rebuilds the widget to reflect the changes. Key Points:  
∙ Stores data that might change during runtime.  
∙ Requires two classes:  
1. The widget class (extends StatefulWidget)  
2. The state class (extends State<WidgetName>)  
Example:  
import 'package:flutter/material.dart';  
class MyStatefulWidget extends StatefulWidget {  
 @override  
 _MyStatefulWidgetState createState() => _MyStatefulWidgetState(); }  
class _MyStatefulWidgetState extends State<MyStatefulWidget> {  int counter = 0;  
 void _incrementCounter() {  
 setState(() {  
 counter++; // Rebuilds UI when counter changes  
 });  
 }  
 @override  
 Widget build(BuildContext context) {  
 return Scaffold( 
 appBar: AppBar(title: Text("Stateful Example")),  
 body: Center(child: Text("Counter: $counter")),  
 floatingActionButton: FloatingActionButton(  
 onPressed: _incrementCounter,  
 child: Icon(Icons.add),  
 ),  
 );  
 }  
}  
Behavior: Each press of the button updates the counter because the widget rebuilds itself with 
new data.

5) b) Implement state management using set state and provider 

Stateful Widgets: Definition: Stateful widgets are widgets that maintain state, allowing them 
to change and update over time in response to user actions, network events, or other factors. 
 Characteristics: 

 They have an associated mutable state that can change during the widget's lifetime.  
 The state is stored in a separate class that extends State and is associated with the 

stateful widget. 
 Changes to the state trigger a rebuild of the widget's UI, allowing dynamic updates.  
 They are ideal for UI elements that need to change or react to user interactions, such 

as input forms, animations, or scrollable lists. 
Stateful widgets are composed of two classes: the stateful widget itself (which extends 
StatefulWidget) and its corresponding state class (which extends State). The state class is 
responsible for maintaining the widget's mutable state and updating the UI accordingly via 
the setState() method.  
stateless widgets are static and immutable, while stateful widgets are dynamic and can change 
over time by managing their internal state. Understanding the difference between these two 
types of widgets is essential for designing and building efficient and responsive Flutter UIs.

What is Provider? 

22 
 



Provider is a state management solution for Flutter. 
It’s basically a way to store data in one place and let multiple widgets listen to changes in that 
data automatically. 

Why Provider is Useful 

✅ Centralized State → You don’t pass variables through constructors over and over. 

✅ Automatic UI Update → No manual setState() in every widget. 

✅ Performance Friendly → Only widgets using the data rebuild. 

✅ Scales Well → Works for small and large apps. 

✅ Cleaner Code → Logic (data) and UI are separated.

What is a Unit Test? 
A unit test checks whether a small piece of code (usually one function or widget) 
works as expected — without running the full app. 
In Flutter, Widget Tests (Unit Tests for UI) check: 

 If the widget displays the correct text or UI elements. 
 If buttons or gestures work as expected. 
 If the widget updates properly when interacted with. 

These tests run without an emulator — they test widgets in isolation (very fast).
