FULLSTACK DEVELOPMENT:
Full-stack development refers to the practice of working on both the front-end
and back-end of a web application or software. A full-stack developer is proficient
in all layers of a software application, including the user interface (front-end),
server-side logic (back-end), and database management. They can handle the
entire development process, from the client-side interactions to the server-side
operations and data storage.
Front-end Development: This involves the user interface, which is what users
interact with directly. This includes elements like the website's design, layout, and
user experience. Common technologies used include HTML, CSS, JavaScript, and
various JavaScript frameworks like React, Angular, or Vue.
Back-end Development: This handles the server-side logic, databases, and
application workflows that run behind the scenes. It manages data storage, user
authentication, and other core functionalities. Popular technologies include
Python, Java, Node.js, and databases like MySQL, PostgreSQL, or MongoDB.
Full-stack development encompasses both these aspects, allowing developers to
build complete web applications from start to finish.
Front-end Technologies:
HTML: HTML stands for Hyper Text Markup Language. It is used to design the
front-end portion of web pages using markup language.
CSS: Cascading Style Sheets
CSS is used to define styles for your web pages, including the design, layout
and variations in display for different devices and screen sizes.

JAVA SCRIPT:
JavaScript is the programming language of the web.

It can update and change both HTML and CSS.

It can calculate, manipulate and validate data.



React is a front-end JavaScript library.

REACT JS:
React was developed by the Facebook Software Engineer Jordan Walke.

React is also known as React.js or ReactJS.

React is a tool for building UI components.

Node js :
Node.js is an open-source, cross-platform JavaScript runtime environment that
allows developers to execute JavaScript code outside of a web browser. It is
built on Chrome's V8 JavaScript engine and enables the use of JavaScript for
server-side scripting, command-line tools, and other applications.

V8 engine :
The V8 engine is Google's open-source, high-performance JavaScript and
WebAssembly engine, written in C++. It is the core component that enables
Node.js to execute JavaScript code outside of a web browser environment.

V8 parses and compiles JavaScript code into machine code, allowing the
computer's processor to understand and execute it directly.

Express js:
Express.js is a minimal and flexible Node.js web application framework that
provides a list of features for building web and mobile applications easily. It
simplifies the development of server-side applications by offering an easy-to-
use API for routing, middleware, and HTTP utilities.

1)Built on Node.js for fast and scalable server-side development.

2)Simplifies routing and middleware handling for web applications.

3)Supports building REST APIs, real-time applications, and single-page
applications.

4)Provides a lightweight structure for flexible and efficient server-side
development.



RESTful API :
A RESTful API, or REST API, is a way for computer systems to communicate
over the internet using a set of architectural principles called Representational
State Transfer (REST). It uses standard HTTP methods like GET, POST, PUT,
and DELETE to access and manipulate resources, often formatted as JSON or
XML.

Here's a more detailed explanation:

Key Concepts:
-----------------------

1)REST (Representational State Transfer):

A set of architectural constraints that define how web services should be
designed.

2)API (Application Programming Interface):

A set of rules and specifications that allow different software systems to
communicate with each other.

3)HTTP Methods:

The standard methods used in RESTful APIs to interact with resources:

->GET: Retrieves a representation of a resource.

->POST: Creates a new resource.

->PUT: Updates an existing resource.

->DELETE: Deletes a resource.

Routing :
In Express.js, routing defines how an application responds to client requests at
specific endpoints, which are combinations of a URI (or path) and an HTTP request



Middleware:
In the context of a client-server architecture, Express.js middleware functions as an intermediary layer
that processes requests and responses as they flow between the client and the server.
A client sends an HTTP request to the Express.js server.
Middleware Interception:
Before the request reaches its intended route handler, it passes through a series of middleware
functions. Each middleware function has access to the request object (req), the response object (res),
and a next() function.
Ex: Authentication/Authorization: Verifying user credentials or permissions
Sessions and cookies:
Sessions and cookies are both mechanisms used by websites to store user information, but they differ in
where the information is stored and how long it persists. Sessions store data on the server-side, while
cookies store data on the user's browser (client-side).
Sessions:
Server-side storage:
Session data is stored on the web server, making it more secure than cookies.
Temporary storage:
Sessions are typically used to store temporary information related to a user's visit, such as login
credentials or items in a shopping cart, and they expire when the session ends (e.g., when the user
closes the browser or logs out).

Cookies:
Client-side storage:
Cookie data is stored on the user's computer in the form of small text files.
Persistent or temporary:
Cookies can be persistent (stored for a specified duration) or session-based (deleted when the browser
is closed).



Single-Page Application (SPA) :
A single-page application (SPA) is a web application that interacts with the user by dynamically rewriting
the current page instead of loading new pages from the server. A real-time example of an SPA is Gmail,
where users can manage their inbox and emails without full page reloads as they navigate between
emails or folders. Other examples include Google Maps, where users can zoom, search, and get
directions without page refreshes, and Trello, where task management and updates happen in real-time
without page reloads.

const express = require('express');
const session = require('express-session');
const sessionrouterapp = express.Router();
// Setup session middleware
sessionrouterapp.use(session({
secret: 'your-secret-key', //🔐 Used to sign the session ID cookie
resave: false, // Don’t save session if unmodified
saveUninitialized: true, // Save uninitialized sessions
cookie: {
maxAge: 1000 * 60 * 1, // Session cookie lifespan (15 mins) 1000 (ms) * 60 (sec) * 30 (min) =

1,800,000 ms
httpOnly: true, // Prevents client-side JS from accessing the cookie
secure: false // Set to true if using HTTPS
//Optional samesite: lax or none, strict

// Value : Behavior
// 'Strict' Cookie sent only for same-site navigation (no cross-site)
// 'Lax' Cookie sent on top-level GET requests (default)
// 'None' Cookie sent on all requests, even cross-site — must set secure: true
}
}));
//The session is about tracking the state of the user who sent the request
//So req.session is a per-user, per-session store
// Route to create session
sessionrouterapp.post('/login', (req, res) => {
const username = req.body.username;
if (username) {
req.session.username = username; // Store user data in session



res.send(`Session started for ${username}`);
} else {
res.status(400).send('Username required');
}
});
// Route to access session
sessionrouterapp.get('/dashboard', (req, res) => {
if (req.session.username) {
res.send(`Welcome back, ${req.session.username}`);
} else {
res.status(401).send('Please log in');
}
});
// Route to destroy session (logout)
sessionrouterapp.post('/logout', (req, res) => {
req.session.destroy(err => {
if (err) return res.status(500).send('Logout error');
res.clearCookie('connect.sid'); // Remove cookie
res.send('Logged out successfully');
});
});
module.exports = sessionrouterapp

authrouter.js
const express = require('express');



const session = require('express-session');
const bcrypt = require('bcrypt');
var authrouter= express.Router();
// Middleware
// authrouter.use(express.json());
authrouter.use(session({
secret: 'super-secret-key',
resave: false,
saveUninitialized: false,
cookie: { maxAge: 1000 * 60 * 30 } // 30 minutes

}));
// Fake "database"
const users = []; // In real apps, use MongoDB/PostgreSQL
// Registration nothing but sign up
authrouter.post('/register', async (req, res) => {
const { username, password } = req.body;
const hashedPassword = await bcrypt.hash(password, 10);
users.push({ username, password: hashedPassword });
res.send('User registered');



});
// Login
authrouter.post('/auth/login', async (req, res) => {
const { username, password } = req.body;
const user = users.find((u) => u.username === username);
if (!user) return res.status(400).send('User not found');
const isValid = await bcrypt.compare(password, user.password);
if (!isValid) return res.status(401).send('Invalid credentials');
req.session.user = user.username;
res.send('Login successful');

});
// Protected route
authrouter.get('/auth/dashboard', (req, res) => {
if (!req.session.user) {
return res.status(401).send('Unauthorized');

}
res.send(`Welcome, ${req.session.user}`);

});



// Logout
authrouter.post('/auth/logout', (req, res) => {
req.session.destroy(err => {
if (err) return res.status(500).send('Error logging out');
res.clearCookie('connect.sid');
res.send('Logged out');

});
});
module.exports = authrouter

<p>You typed: {inputValue}</p>
</div>

<div>

</div>
</div>
);
}

App.js:
const express = require("express");
const bodyParser = require("body-parser");
const path = require("path");
const app = express();
const PORT = 4000;
// Middleware
app.use(bodyParser.urlencoded({ extended: true }));
app.use(express.static(path.join(__dirname, "public")));
// Set view engine and views directory
app.set("view engine", "ejs");
app.set("views", path.join(__dirname, "views"));
// Temporary task storage
let tasks = [];
// Routes
app.get("/", (req, res) => {
res.render("index", { tasks });
});
app.post("/add", (req, res) => {
const newTask = req.body.task;
if (newTask) tasks.push(newTask);
res.redirect("/");
});



app.post("/delete", (req, res) => {
const index = parseInt(req.body.index, 10);
if (!isNaN(index) && index >= 0 && index < tasks.length) {
tasks.splice(index, 1);
}
res.redirect("/");
});
// Start server
app.listen(PORT, () =>
console.log(`✅ Server running at http://localhost:${PORT}`)
);
